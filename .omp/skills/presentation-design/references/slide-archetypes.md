# Slide archetypes

Choose an archetype from the message and the established Design DNA, not from a generic component library. An archetype controls the reading path; it is not a reason to add decoration.

- **Title or section**: establish the topic or transition with one dominant read and enough space to reset attention.
- **Assertion**: lead with one claim, then place only the evidence needed to support it.
- **Comparison**: give alternatives equivalent structure so the difference, not the container treatment, carries the message.
- **Process**: make sequence, direction, and handoff explicit; use one path rather than competing flows.
- **Evidence**: make the chart, quote, number, or image the focal read and retain the context needed to interpret it.
- **Image-led**: let the image carry the subject while type supplies a concise frame; crop intentionally inside its frame.
- **Close**: restate the intended takeaway or action with a clear final hierarchy.
- **Architecture or system explanation**: lead with the relationship the audience must understand—ownership, containment, sequence, interface, or exchange—then use only the views needed to make that relationship legible. Name the parts and the relationship; a diagram is evidence for the claim, not decoration.

## Multi-diagram topology

Use more than one diagram only when the message requires multiple reader questions whose relationship is itself meaningful. Select the topology from that relationship, retain one clear overall reading path, and make the connection between views explicit in labels, shared anchors, or connectors.

- **Paired**: place two peer views together when the audience must compare complementary states, perspectives, or responsibilities. Give each a distinct reader question and a visible basis for comparison; do not duplicate the same diagram merely for symmetry.
- **Stacked**: arrange views in reading order when one level, stage, or consequence depends on the preceding one. Make the downward or upward dependency explicit rather than presenting unrelated panels as a vertical list.
- **Nested**: place a view within another when it explains true containment, scope, scale, or an internal subsystem. Preserve enough boundary and context to distinguish “inside” from simply “near.”
- **Bridged**: connect otherwise separate views when the message is the handoff, translation, dependency, or flow between them. Label what crosses the bridge and its direction; the bridge must carry meaning, not ornament.

Each view must answer its own reader question at presentation distance, and the audience must be able to state why the views appear together. If a single diagram answers the message more clearly, use one.

Vary adjacent archetypes when the narrative benefits from a change in rhythm, but preserve the deck’s anchors, type scale, color roles, and density.
